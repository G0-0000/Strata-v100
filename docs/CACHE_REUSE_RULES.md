## 规则条文

- **R1 版本变化 → KV 测试 → 合格进表 → 不合格才报。**
  引擎版本（含本地修订号）变化后，对同模型、异配置之旧缓存，程序须先做 KV 测试；合格者全部写入
  账本并进表复用；不合格者才报「另一配置身份」并拒绝。
- **R2 验证之前不得判死。**
  账本尚空、KV 测试未跑时，不得将同模型异配置缓存判为无效、不得打印「建议删除」、更不得删除文件。
- **R3 会话文件与磁盘缓存同一规则。**
  两者共用同一读取函数、同一本账、同一个验证工具（cache_verify.py），仅目录/文件参数不同。
- **R4 验证由程序自动执行。**
  不得要求运维先手工跑工具再启动；程序（启动流程）自行完成 KV 测试与进表。
- **R5 提交必记原规则。**
  凡涉上述行为之 git 提交，message 须含 `Owner-rule:` 段，引用本文件并列原规则原文。
